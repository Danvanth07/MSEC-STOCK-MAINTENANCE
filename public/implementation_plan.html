🏛️ 1. Institutional Profile & Project Vision

1.1 Institutional Context

Mohamed Sathak Engineering College (MSEC) is an autonomous engineering institution pioneering technical education in Kilakarai, Ramanathapuram District, Tamil Nadu. With dozens of academic departments, specialized laboratories, research centers, and thousands of students, the college requires an authoritative, auditable, and unified resource management platform.

1.2 System Vision

MSEC SMART STOCK replaces disconnected paper registers, decentralized spreadsheets, and ad-hoc email approvals with a single source of truth across the campus lifecycle: Procurement: Vendor directory, 3-quote comparative statements, POs, and GRNs. Warehouse Control: Central Stores custody, bin locations, minimum safety thresholds, and stock adjustments. Academic Allocation: Laboratory assets, departmental consumables, inter-department transfers, and returnable gate passes. Governance & Compliance: Multi-tier monetary approvals, permanent audit logs, and one-click statutory reports for NAAC (Criteria 4) and NBA (Criterion 6 & 8) accreditation.

⚙️ 2. Master Architecture & Technology Stack

2.1 Technology Stack Architecture

Server Runtime: PHP 8.2+ (Modular OOP architecture, PSR-4 styled autoloading, PDO database abstraction). Database Engine: Dual Engine Strategy: - Local / Development: Portable, zero-configuration SQLite 3 (database/msec_stock.sqlite) pre-seeded with 14 role personas, real institutional items, vendors, and transactions. - Production / Deployment: Enterprise MariaDB 10.4+ / MySQL 8.0 (database/schema_mysql.sql and database/seed_mysql.sql) via XAMPP. Presentation Tier: Pure Vanilla CSS Design System (public/css/style.css) with zero external CSS frameworks (no Tailwind/Bootstrap bloat), CSS Custom Properties (Tokens), and dynamic clamp-based responsive typography. Client Interactivity: Lightweight Vanilla JavaScript (public/js/app.js) handling real-time searches, multi-item dynamic tables, modal dialogues, and print stylesheets.

3.1 Adaptive Cross-Device Display Engine

A key institutional requirement is that the UI must look sharp, comfortable, and perfectly proportioned on every device without horizontal scrollbars or clipped text: High-Resolution Desktop PCs (1080p, 1440p, 4K): Generous content gutters, 2-column KPI card layouts, wide data tables with clean typography. 🔒 5. Core Institutional Workflows & Non-Negotiable Rules

Rule 1: The Store Keeper Operational Gateway

The Central Store Keeper is never bypassed at MSEC. Even for a ₹1 requisition, every request must pass through the Store Keeper for: 1. Verification against current warehouse balances (preventing duplicate purchases). 2. Existing stock check and specification review. 3. Official Approval Sheet generation before financial sanctions are executed. 4. Material receipt (GRN) and official Delivery Challan / Issue Voucher dispatch.

Rule 2: Admin-Controlled Security (Zero Self-Service Resets)

To maintain strict institutional accountability: No Public Self-Registration: Accounts are provisioned exclusively by the System Administrator. No Public Password Reset Links or OTPs: If an employee forgets their password, they must contact the Central IT Administrator. The administrator verifies their identity and issues a secure reset through the Admin Console. Brute-Force Lockout: 5 consecutive failed attempts lock the account automatically, requiring administrator unlocking.

Rule 3: Monetary Approval Threshold Matrix

All requisitions follow an automated approval ladder based on estimated value: Tier 1 (Below ₹5,000): Requester → Dept Coordinator → HOD → Central Store Keeper. Tier 2 (₹5,001 – ₹25,000): Tier 1 approvals + Vice Principal Sanction. Tier 3 (₹25,001 – ₹1,00,000): Tier 2 approvals + Principal Institutional Sanction. Tier 4 (Above ₹1,00,000): Tier 3 approvals + Director Executive Sanction.

📦 6. Detailed 10-Module Implementation Specifications

Module 1: System Administration, User Accounts & Audit Trails

 Files: views/admin/users.php, views/admin/security.php, views/admin/audit.php, core/Auth.php, core/AuditLogger.php Features: User CRUD, role assignment, active/locked toggle, admin password reset with prefilled secure credentials, and immutable logging recording user ID, action, before/after JSON states, IP address, and timestamps.

Module 2: Master Inventory & Real-Time Stock Tracking

 Files: models/Inventory.php, views/inventory/index.php Features: Consumable vs Non-Consumable cataloging, Department Store balances, Central Warehouse balances, bin/shelf locations, minimum safety stock thresholds, and Stock Adjustments (requiring formal justification and document reference).

Module 3: Stock Requisitions & Indent Lifecycle

 Files: models/Request.php, views/requests/index.php, views/requests/view.php Features: Indent raising with auto-generated format (CSE-REQ-2026-00125), multi-item specification lines (Item, Quantity, Purpose, Estimated Unit Cost), and status lifecycle progression (Draft → Submitted → Under Review → Approved → Fulfilled).

Module 4: Dynamic Approval Engine & Approval Sheets

 Files: core/ApprovalEngine.php, views/approval_sheets/view.php Features: Evaluation of monetary thresholds, routing to correct authority tier, digital approval/rejection decision recording with mandatory review remarks, and printable Official Approval Sheets.

Module 5: Stock Distribution & Delivery Challans

 Files: models/Distribution.php, views/distribution/index.php, views/distribution/voucher.php Features: Issuing stock from Central Store to Department Stores (CSE, ECE, Mech), generation of printable Official Issue Vouchers with barcode visual and 3-party signature blocks (Store Keeper, Department Receiver, Principal/VP), and digital acknowledgment updating department inventory.

Module 6: Stock Movement & Inter-Department Transfers

 Files: models/Movement.php, views/movement/index.php Features: Cross-department transfers (e.g., CSE to ECE 5 Keyboards), transit status tracking (Submitted → Approved → Dispatched → In Transit → Acknowledged), and automated stock balance synchronization upon acknowledgment.

Module 7: IT Asset Management & Hardware Maintenance

 Files: models/Asset.php, models/Maintenance.php, views/assets/index.php, views/maintenance/index.php Features: Asset registry capturing Serial Number, MAC Address, IP Address, Configuration (CPU/RAM/SSD), AMC details, and Warranty dates; damage fault reporting modal (serviceModal), maintenance logging, and condemnation workflows.

Module 8: Procurement, Vendor Management & Purchase Orders

 Files: models/Procurement.php, views/procurement/index.php, views/procurement/po.php Features: Vendor onboarding (GSTIN, PAN, bank info, ratings, blacklist toggle), 3-quote comparative statement matrix with L1 lowest-bidder recommendation, official printable Purchase Orders with auto-calculated GST and net totals, and Goods Receipt Notes (GRN) for material inward inspection.

Module 9: Physical Stock Verification & Dead Stock Watchlist

 Files: views/verification/index.php, models/Inventory.php Features: Periodic physical count audits, system vs physical count discrepancy logging, variance justification, and Dead Stock Watchlist tracking items idle for 1, 2, or 3+ years.

Module 10: Statutory Reports & NAAC / NBA Accreditation Analytics

 Files: models/Report.php, views/reports/index.php Features: 5 locked statutory report groups: 1. Stock Reports: Current valuation, low-stock warnings, category distribution. 2. Movement Reports: Fast-moving vs slow-moving items, inter-department transit history. 3. Consumption Reports: Department-wise and lab-wise consumption expenditure. 4. Financial Reports: Budget utilization, PO commitments, annual capital expenditure. 5. Audit Reports: NAAC Criteria 4 IT infrastructure assets, NBA lab equipment logs, physical audit histories.

🚀 8. Step-by-Step Multi-PC Git & Branching Protocol

8.1 Setup on Each Team Member's Computer

Each junior developer clones the central repository and checks out their assigned branch: 
# Clone the repository
git clone https://github.com/tech-shakil/msec-smart-stock.git
cd msec-smart-stock


Switch to assigned feature branch:

git checkout -b feature/asset-management         # (For Junior 1)
git checkout -b feature/stock-movement          # (For Junior 2)


Start local server (Zero database config required; SQLite is pre-seeded):

run.bat

(Or: php -S localhost:8000 -t public)



Open in browser: http://localhost:8000

8.2 Submitting Work (Pull Request Workflow)

When a developer completes their tasks: 
# Stage and commit only their assigned files
git add <assigned_files>
git commit -m "feat(<module>): implement assigned features and test cases"


Push to their feature branch

git push origin <feature_branch_name>
The developer then visits GitHub and opens a Pull Request (PR) targeting the main branch.

8.3 How the Team Lead (Muhammad) Merges

1. Open each Pull Request on GitHub. 2. Inspect Files Changed to verify the developer stayed within their file boundaries. 3. Click Merge Pull Request → Confirm Merge. 4. Pull the merged code down to the Lead PC: 
git checkout main
   git pull origin main

🗄️ 10. Database Architecture & Seed Reference

The database includes 17 relational tables supporting both SQLite and MySQL/MariaDB: users: User credentials, bcrypt password hashes, role keys, failed attempts, and lock status. departments: Academic and administrative departments with HOD mappings. laboratories: Departmental labs with Lab In-Charge mappings. categories & subcategories: Hierarchical classification for consumables, IT equipment, stationery, and lab apparatus. items: Master catalog with SKU codes, unit definitions, safety thresholds, and unit costs. inventory: Live stock levels per department store and central warehouse with bin locations. stock_adjustments: Historical adjustments with mandatory reason and document references. stock_requests & stock_request_items: Indents with line-item quantities and estimated costs. approvals: Multi-tier approval actions, decision stamps, and reviewer comments. vendors: Supplier directory with GSTIN, PAN, and rating metrics. purchase_orders & po_items: Generated POs, delivery terms, and tax calculations. goods_receipts & grn_items: Material inward inspection and warehouse increment logs. stock_issues & stock_issue_items: Issue orders and delivery vouchers. stock_transfers: Inter-department transfer tracking with full transit lifecycle. assets: IT and laboratory hardware tracking with MAC, IP, configuration, and warranty. maintenance_logs: Service tickets, breakdown costs, and repair statuses. audit_logs: Immutable security and transaction trail.
